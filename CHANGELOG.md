# Changelog

## 2026-10-01, a missing resource gets the error code of the revision the client speaks

- **The MCP server answers a resource that doesn't exist with the code of the protocol revision the client speaks** (chapter 12, the MCP server; this change belongs with that chapter). `python/src/helpdesk/mcp_server.py`'s `not_found` answered every resource that doesn't exist, and every ticket the person can't see, with JSON-RPC error -32602 in both of the eras it serves on stdio. That is right for 2026-07-28: its resources page (`modelcontextprotocol.io/specification/2026-07-28/server/resources`, Error Handling, read 2026-10-01) says "If the requested resource does not exist, servers MUST return a JSON-RPC error with code `-32602` (Invalid Params)", and asks clients to accept -32002 too, "as earlier protocol versions used this code". But the 2025-11-25 page (`modelcontextprotocol.io/specification/2025-11-25/server/resources`, read the same day) lists "Resource not found: `-32002`", as the 2025-06-18, 2025-03-26 and 2024-11-05 pages do, so a host that opened with the initialize handshake and looks for -32002 didn't recognize the server's answer. Now `not_found` takes the request's context and answers -32002 (`RESOURCE_NOT_FOUND`; the SDK names only the current code) when `ctx.protocol_version`, the revision the SDK keeps from the handshake or from the request's own metadata, is one of the SDK's `HANDSHAKE_PROTOCOL_VERSIONS`, and -32602 otherwise, with the same message and data either way. Over HTTP the server speaks only 2026-07-28, so its answers are unchanged, and `python/src/mcp_governance/resource_server.py` builds no such error. Shown by `python/tests/test_mcp_server.py::test_a_missing_resource_gets_the_code_of_the_revision_the_client_speaks`, written first: a missing ticket, a hidden one, a missing article and a URI that names nothing, read in each era, get -32602 after `server/discover` and -32002 after the 2025-11-25 handshake, with the same words; before the fix it failed with `assert [-32602, -326...32602, -32602] == [-32002, -320...32002, -32002]` (`pytest`, 763 passed, was 762). The file's other -32602 assertions read through the 2026-07-28 client or aren't about a missing resource (a request without its metadata, an unknown tool, a refused prompt), so they stay. A new entry in `tools/mutations.mjs` (784, in 89 groups), under `mcp:`, removes the era check, so the legacy read gets -32602. Checked with: `node check.mjs`, all 27 checks passed; `node tools/doc-claims.mjs .` and `node tools/kit.mjs changelog CHANGELOG.md`, no problems; and `node tools/mutate.mjs --only "mcp:"`, 10 entries, run on this change as committed, before it was pushed: every entry caught.

## 2026-10-01, the budget measures a provider's own turn objects

- **A real multi-turn tool run is no longer stopped by its own cap's estimate** (chapter 23, the cap on billed runs; this change belongs with that chapter). `python/src/helpdesk/model/budget.py`'s `request_json` wrote each message with `json.dumps` after the Anthropic adapter's `to_api`, which sends the model's turn back as its `raw`: with a real SDK, the provider's own response objects (Anthropic's content blocks, OpenAI's output items, both pydantic models), which `json.dumps` can't write. So `request_chars`, the estimate the budget checks against the cap before every call (and the gateway's, chapter 27, which also keys its cache on `request_json`), raised `TypeError` before the second call of any real tool run. On the mock, `raw` is `None` or plain data, so nothing had shown it; an Anthropic `TextBlock` and an OpenAI `ResponseFunctionToolCall`, built from the installed SDKs with no call made, each raised it. Now `request_json` and `response_chars` write through `as_json`, `json.dumps` with a `default` (`plain`) that gives a pydantic model's `model_dump(mode="json")`, a dataclass's fields, and anything else its text. Plain data measures exactly as before, so `test_the_budget_measures_a_request_as_the_patterns_do` still holds. `prompt_json` is unchanged, since only the system prompt and the tools reach it, and so are `python/src/helpdesk/gate.py`'s fingerprints, which cover the configuration, never a turn. A new entry in `tools/mutations.mjs` (783, in 89 groups), under `budget:`, removes the `default`.
